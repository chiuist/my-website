核心流程概览

bilibili 游戏开放平台（open.biligame.com）是游戏发行的操作入口，覆盖企业入驻、游戏创建、页面预约、测试包分发和正式发布。主要操作在后台完成；测试资格、资源曝光和部分异常处理需由平台运营或商务确认。

本手册业务边界：平台仅支持企业开发者入驻。本项目采用官包 / 自主运营分发：不接入 bilibili 游戏 SDK，不建立独立 B 服，不使用 B站账号或 B站支付；游戏继续使用现有手机号账号、自有服务器、自有支付、实名防沉迷和客服体系。

合作确认：在首次提交预约或测试前，由发行取得平台书面确认：允许使用自有账号与自有支付的官包分发方式，并确认包体处理、测试资格、付费测试、资源曝光和数据回传要求。游戏流水不按 B站 SDK 联运结算。

首发独占要求：若您在 bilibili 平台使用了游戏预约或测试服务，您应保证该游戏最终在 bilibili 平台上实现发布和运营，且发布（含开放预下载）和运营的时间均不能晚于您自己或其他第三方在内的任何合作渠道、平台或网站。

1. 开发者入驻与认证

1.1 登录并加入游戏开放平台

前往 open.biligame.com，使用 bilibili 账号登录，点击「加入我们」进入企业开发者入驻流程。平台仅开放企业开发者入驻。

1.2 企业资料准备

材料类别主要信息关键限制
账号与展示信息 bilibili 账号、账号昵称、公司全称、开发者昵称/认证称号等 公司及展示名称应真实、规范并与主体关系可核验
业务联系人 姓名、手机号、邮箱、身份证信息及证件照片等后台要求字段 填写真实在职联系人，确保可接收审核、合同和应急通知
企业主体 营业执照、统一社会信用代码、企业认证函、法定代表人及身份证件、注册地址等 认证函须使用游戏开放平台提供的模板并加盖企业公章
财务与税务 银行账户、收款与开票信息、纳税人信息、发票和财务联系人等 账户主体、开票主体和合同主体需按后台及合同要求保持一致

资料变更限制：开发者主体信息提交后，仅部分业务联系人字段可在线维护。公司昵称、主体或财务信息变更需按平台人工流程处理，财务变更可能从下一结算周期生效。

1.3 创建游戏

企业信息填写后，在「游戏管理 → 创建游戏」选择 Android 非付费下载、Android 付费下载、PC 或平台当前开放的其他类型，填写游戏名称、合作类型和基础资料。游戏名称应与版号或权利材料保持一致。

  • 上传软件著作权登记证书或相应权利/授权链材料
  • 上传版号、审批文件及运营授权；暂缺特定审批材料时，创建/签约页面可能允许提交平台模板承诺函
  • 承诺函用于创建或签约阶段的材料受理；正式发行前仍须取得版号并完成 APP 备案

完成后状态：提交企业和首个游戏资料后进入平台审核及必要的合作确认流程；审核通过并确认官包分发权限后，即可安排页面、预约和测试，不进入 bilibili SDK 接入流程。

2. 合作确认与官包分发

2.1 平台审核与合作确认

游戏创建后，按后台要求提交主体、权利资质和页面资料。预约、测试或正式下载前，完成平台要求的审核及必要协议，并由发行确认本项目采用官包 / 自主运营分发，不启用 bilibili SDK 联运能力。

确认开发者主体

核对企业主体、业务联系人、游戏运营单位和权利链；后台主体应与 APP 备案、版号和隐私政策中的实际运营主体一致。

上传游戏资质

提交软著/权利授权、版号/运营授权等材料。暂缺特定审批材料时可按页面要求提交盖章承诺函；正式发行前须补齐相应资质。

确认官包分发模式

书面确认游戏使用自有手机号账号、自有服务器、自有支付、实名防沉迷和客服体系；B站仅提供页面、预约、测试、下载分发和曝光，不单独开设 B 服。

确认测试与付费边界

确认删档不计费、删档付费和正式上线均可上传现有官包；1 月付费测试继续使用游戏自有支付，并按平台要求提交版号、APP 备案、实名防沉迷和支付合规材料。

归档平台确认

保存后台审核结果、邮件、工单或协议，记录包体是否会被平台处理、送审时限、资源位申请、测试资格及数据回传要求。

2.2 官包 / 自主运营职责边界

能力 责任方 执行方式
账号登录与角色数据 游戏方 沿用现有手机号账号和官服角色体系，三渠道用户进入同一服务器体系
支付、订单与退款 游戏方 沿用游戏自有支付和订单系统；不接入 B站支付，不参与 B站 SDK 流水结算
实名、防沉迷与注销 游戏方 使用现有官服合规体系，隐私政策和账号注销入口覆盖从 B站下载的用户
页面、预约、测试与下载 bilibili 平台 平台提供游戏页、预约、测试包/正式包下载和站内曝光，具体资源以运营确认结果为准

确认要求：开放平台协议允许符合要求的游戏选择接入 SDK，同时也要求非平台登录或支付取得平台许可。本项目使用自有账号与支付，因此必须保留平台同意官包自主运营模式的书面记录；不得仅凭其他游戏案例直接推定本项目已获许可。

3. 创建游戏与物料准备

3.1 游戏创建

进入「游戏管理」创建游戏，选择游戏类型。游戏类型创建后不可修改，请按官包 / 自主运营分发模式选择对应类型，并确认页面、预约、测试和正式下载权限；不创建 SDK 联运渠道包。

3.3 游戏分类与标签

  • 游戏分类：MMORPG/策略/动作/多人对战/放置/格斗/回合战略/即时战略/角色扮演/解谜/竞速/卡牌/类 Rogue/模拟经营/跑酷/沙盒/射击/体育竞技/文字/休闲/养成/益智/音乐节奏
  • 标签 Tag：最多 5 个，是对游戏的另一种描述，提供更加准确具体、更多维度的关键内容标记
  • 开发商名/运营商名：请精简厂商名称，如"上海哔哩哔哩科技有限公司"精简为"哔哩哔哩"

3.4 bilibili 角标与品牌规范

游戏打包前必须将 APK 包中的 ICON 文件添加 bilibili 渠道角标，以作标识。

  • 游戏内 ICON 必须为圆角，1024×1024 尺寸下圆角弧度为 230px
  • 开放平台正式服/测试服详情页资料更新页面需额外单独使用一份 PNG 图片：512×512 直角 ICON
  • 角标位置固定在 ICON 右下角
  • res/drawable 内所有分辨率均需添加角标，角标分辨率无强制要求，清晰即可
  • 不得遮挡图标主题内容和文字区域

品牌标志规范：新发布的视频统一使用 bilibili 游戏粉色品牌标志（#FF5588），并按平台提供的角标与品牌素材规范制作。

4. 开放预约

4.1 申请预约

游戏创建、资质审核和签约完成后，可在「游戏管理 → 游戏名称 → 申请预约」提交预约页面资料。首次填写后的部分物料可在后续阶段继承，但仍须在每次提交前核对当前内容。

正式包是不可逆节点：一旦提交正式包，即使正式包尚未实际上线，也不能再次开启预约或测试。提交正式包前必须确认预约活动、奖励配置、测试收尾和资格发放均已完成。

4.2 预约奖励

在「游戏运营 → 预约奖励」配置奖励。支持预约即得奖励和最多 5 档预约里程碑，可在公测后通过游戏内邮件或礼包码发放。奖励配置需审核；审核后允许的调整不能降低已公布档位，礼包码发放方式、数量等字段存在不可修改项，提交前须按后台提示逐项复核。

4.3 预约期运营

  • 建议上传/关联游戏相关视频（B 站视频生态为核心流量来源）
  • 利用 bilibili 主站内容生态：UP 主合作、游戏区投稿、直播联动
  • 期待更新/上线时间：可设置审核通过后立即发布或自定义时间

5. 测试阶段

5.1 测试类型

bilibili 新游测试有三种状态，测试类型不可回退，请谨慎选择：

测试类型 说明 适用场景
删档不计费 测试数据不保留，无内购付费 早期玩法验证、技术测试
删档计费 测试数据不保留，但开放内购付费 付费验证、经济系统测试
不删档计费 测试数据保留，开放内购付费 准公测、长线运营前验证

不可回退规则：如已开启删档计费测试，则无法再开启删档不计费测试；同理，如已开启不删档计费测试，则无法再开启删档计费测试。建议开启不删档计费测试时，选择提交正式包。

5.2 提交测试包流程

仅提交资料 / 提交测试包与资料

入口：「游戏管理」→「游戏名称」→「仅提交资料」或「提交测试包与资料」。首次建议选择「提交测试包与资料」。

填写测试资料

按物料清单准备的所有内容依次填入，可进行手机端预览和 PC 端预览。

确认官包信息

使用与 TapTap、好游快爆一致的现有测试官包，沿用已完成 APP 备案的实际包名、签名、账号和服务器体系；不新增 .bilibili 包名，不制作 SDK 渠道包。包名、版本号和备案信息须与上传 APK 一致。

上传官包 APK

上传已完成内部验收的非加固包或加固包，建议同时兼容 32 位/64 位。若后台对上传包进行重新封装、签名或其他处理，应下载实际分发包完成安装、登录、实名、防沉迷、支付和核心玩法冒烟测试；不预设平台一定会重签。

提交自检报告与兼容性报告

自检报告由 bilibili 提供的自检工具生成（下载自检工具）。兼容性报告按必填材料准备，提交时根据后台字段或平台工单要求完成上传。

设置开服与上线时间

开服时间为服务器正式开启时间（非包体下载时间）。期待包体发布时间可审核通过后立即发布或定时发布。期待包体下线时间到期后自动下架。

提交审核

至少提前 5 个工作日提交包体，并为审核和补件预留时间。测试资料审核通过后生成测试服页面，并按后台期待时间发布。

5.3 测试包体清单

自有支付说明 计费测试/正式上线前确认 说明使用游戏自有支付、订单、退款和客服体系，并保留平台允许该模式的书面确认；不配置 B站 SDK 支付回调

备案识别码 计费测试必填 由游戏运营主体在国家新闻出版署防沉迷实名验证系统完成游戏备案；如平台另要求渠道关系材料，以后台和书面通知为准

更新详情 必填 最多 4000 字，玩家可见

5.4 测试服特性

  • 测试服评分与正式服评分独立，测试服评论不会影响正式服评分
  • 测试期间，测试服页面开放包体下载；非测试期间保持查看状态，引导用户跳转至正式服页面预约
  • 测试状态下，游戏无法申请停运下线
  • 计费测试需资质齐全，否则不予审核通过

6. 正式上线 / 首发

6.1 首发条件

  • 合作确认：完成平台审核及必要协议，已书面确认官包 / 自主运营分发、自有账号与支付的适用范围
  • 权利与出版：软著或完整权利授权链、版号、运营单位授权和游戏名称一致
  • 工信部 APP 备案：现有官包应用名称、包名、主体和签名信息与 APP 备案一致；无 APP 备案不能发布分发
  • 实名与防沉迷：沿用游戏官服的实名、防沉迷和游戏备案体系，从 B站下载的用户与其他渠道用户执行相同规则
  • 技术审核：自检报告、兼容性材料、APK、版本号、隐私、账号注销、防沉迷和自有支付均按后台要求完成自测和审核

提交前最后确认：正式包一经提交，即使尚未实际上线，也不能再开启预约或测试。必须先完成预约奖励确认、测试收尾、用户通知和数据处理，再操作正式包提交。

6.2 首发操作

提交正式包

按正式上线标准填写资料、APP 备案信息并上传与其他渠道一致的官包 APK。至少提前 5 个工作日提交，并为审核与补件预留时间。

完成平台审核

核对包名、版本、实际分发包、备案、资质、自检和页面资料。全部通过后再按期待时间开放预下载和下载；游戏使用既有官服，不单独安排 B 服开服。

版本更新与运营

正式上线后需持续更新：优化开发、运营活动、版本补丁、安全异常修复、BUG 修补等。

6.3 运营要求

  • 版本同步：上传游戏的版本均不能低于含您自己及其他第三方在内的任何合作渠道、平台或网站提供的最新版本
  • 用户服务：确保 bilibili 平台的用户服务和福利均不能低于任何其他合作渠道

  • 内容过滤：接入平台文字/图片安全检测接口
  • 外挂防护：防止服务器和技术设备免遭外挂攻击，发现后需提供有效解决方案

8. 常见问题（FAQ）

Q1：个人开发者能入驻 bilibili 游戏开放平台吗？

不能。bilibili 游戏开放平台仅支持企业开发者。除营业执照和企业公章认证函外，还需按后台提交法人、业务联系人、银行、税务、开票和财务联系人等完整资料。

Q2：本项目是否接入 bilibili SDK 或单独开 B 服？

不接入，也不开 B 服。本项目采用官包 / 自主运营分发：B站承担页面、预约、测试、下载和曝光，游戏方继续承担账号、服务器、支付、实名防沉迷、数据、客服和版本运营。

Q3：测试类型选错了能改吗？

不能回退。如已开启删档计费测试，则无法再开启删档不计费测试；已开启不删档计费则无法再开启删档计费。平台建议不删档计费衔接正式包，但正式包提交后不能再预约或测试，必须先完成所有活动和测试收尾。

Q4：bilibili 会对 APK 包做什么处理？

官包模式下不预设平台一定会二次签名或注入组件。提交前由发行核对后台提示；如平台对包体进行重新封装、签名或其他处理，研发须下载实际分发包完成冒烟测试，并确认不会改变自有账号、支付和服务器体系。

Q5：包名有什么要求？能修改吗？

使用现有官包的实际包名，不新增 bilibili 专属后缀。包名必须与 APK、APP 备案、隐私政策和后台提交信息一致；首次提交前应确认无误，后续能否修改以后台规则为准。

Q6：测试服评分会影响正式服吗？

不会。测试服评分与正式服评分独立，测试服的评论不会影响到正式服评分。

Q7：从 B站下载的用户使用什么账号和支付？

使用与 TapTap、好游快爆一致的游戏自有手机号账号和自有支付，进入同一官服。由于开放平台协议要求非平台登录或支付取得许可，发行需在首次提交前归档平台对本项目官包模式的书面确认。

Q8：游戏版本需要与其他渠道同步吗？

是的。上传游戏的版本均不能低于含您自己及其他第三方在内的任何合作渠道、平台或网站提供的最新版本。同时 bilibili 平台的用户服务和福利均不能低于任何其他合作渠道。

Q9：计费测试需要哪些额外资质？

除基础资质外，计费测试需核验版号/运营授权、APP 备案、防沉迷游戏备案识别码、自有支付与退款流程及平台要求的其他材料。该识别码不属于 ICP 或 APP 备案；具体后台字段以提交当日页面和书面通知为准。

Q10：预约/测试后能否延迟在其他渠道首发？

不能。若您在 bilibili 平台使用了预约或测试服务，您应保证该游戏在 bilibili 平台上的发布和运营时间均不能晚于任何其他合作渠道。

Q11：APP 备案和游戏备案识别码可以二选一吗？

不能。APP 备案属于工信部 APP 互联网信息服务备案；游戏备案识别码属于国家新闻出版署防沉迷实名验证系统的游戏及渠道关系标识。两者主管系统、用途和提交位置均不同。

9. 拓展板块

9.1 bilibili 小游戏

本手册仅覆盖 Android 手游官包 / 自主运营分发，不覆盖 bilibili 小游戏。若未来另立小游戏项目，应单独编制流程，不沿用本手册。

  • 在游戏开放平台确认小游戏创建和测试权限
  • 在技术投入前由商务书面确认运行环境、审核、支付/广告、数据和商业化条款
  • 另行确认其技术方案，不接入当前手游项目的发行排期

9.2 内容生态联动

bilibili 的核心优势在于视频内容生态，建议充分利用：

  • UP 主商业合作：与游戏区 UP 主合作制作试玩、攻略、测评视频
  • 官方投稿：在游戏详情页关联视频 BV 号，引导流量
  • 直播联动：与主播合作进行游戏直播推广
  • 特色专题：参与 bilibili 游戏中心官方专题活动
  • 品牌植入与联动：与 bilibili 主站内容打通，形成立体呈现
